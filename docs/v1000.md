# Building v1.0.0.0

The tree builds both releases of `HYPERX.EXE` from one source. v1.0.0.1, the June 2000 patch, is
the matched build. v1.0.0.0, the October 1996 retail release, is the second target, `HYPERX100`.

## Status

v1.0.0.0 came from Visual C++ 4.0 (linker 3.00) with an incremental link: its `.text` starts with
3042 jump thunks, and its divisions go through the Pentium FDIV check. That toolchain is not in
this repository yet, so the `v100` preset builds the v1.0.0.0 source with VC6 SP3. Its reccmp
scores show which functions pair and roughly how close they are. They do not measure a match.
When the VC4 toolchain is in, the markers and `#ifdef` blocks stay as they are and the scores
start to mean something.

## Building

```sh
cmake --preset v100 -DVC6_ROOT=<your VC6 SP3 tree>
cmake --build build-v100
python -m reccmp.tools.asmcmp --target HYPERX100 --json build-v100/report.json --silent
```

`HYPERX_V100` defines `HYPERX_V100` for every source. The build reads the resources from your own
v1.0.0.0 copy, which `reccmp-user.yml` names under `HYPERX100`.

## Markers

A function in both releases carries one marker for each, v1.0.0.0's directly above v1.0.0.1's:

```cpp
// FUNCTION: HYPERX100 0x0048e490
// FUNCTION: HYPERX 0x0044c160
int GameApp::MainUpdate(HWND hWnd)
```

The `HYPERX` marker stays next to the declaration, because the repository's tools read the line
under it. A function only v1.0.0.0 has carries the `HYPERX100` marker alone, inside
`#ifdef HYPERX_V100`.

2,485 v1.0.0.0 functions carry a marker: 2,326 of the 3,529 game functions with a real start,
93% of v1.0.0.0's game code by size. They come from, in order:

- The two builds' plan dispatch tables, paired slot by slot.
- String anchors from `tools/fpo_anchors.py`, and functions checked by hand.
- A scored matcher. It compares imported calls, string literals, float constants, struct field
  offsets and the call graph, and takes a pair only when each side is the other's clear best. It
  got every one of the 266 hand-checked pairs it reached right with none of them seeded, and every
  one of 299 held-out pairs.
- Vtable slots of tables already paired, and the order of calls in paired functions, which tells
  apart the copies 1.0.1 keeps per screen (`LeagueSetupUIScreen` and `ChampionshipSetupUIScreen`).
- A function-by-function pass over what was left: out-of-line copies of the decomp's inline
  functions take their marker above the inline definition.

The rest is mostly compiler-generated code (static initialisers, deleting destructors, unwind
funclets) and C runtime, neither of which is marked. Where v1.0.0.0 keeps several identical copies
of one function, as it does for every pool's `Insert` and `Destroy`, one copy carries the marker
and the others none. A dead v1.0.0.0 copy never stands in for a live function: v1.0.0.0's unused
`year.cat` parser reads `DefineTeam` first, as `GameEngine::ParseTeamHTMFile` does, and is not its
counterpart. Markers sit on a function's real start, before the `nop` that follows some prologues.

Adding lines to some headers moves VC6's code for v1.0.0.1, even inside `#ifdef HYPERX_V100`: the
inline functions after them change line number. `string.h` and `planvm.h` are two such headers, so
their v1.0.0.0-only functions live in `stringv100.cpp` and `planvmv100.cpp`. After any header change,
check that the v1.0.0.1 build still hashes the same.

## What the patch changed

Each difference is an `#ifdef HYPERX_V100` block.

| Readme item | Function | v1.0.0.0 |
|---|---|---|
| [1] `-x` | `GameApp::ParseCommandLine` | `-x` clears both software-renderer flags, so it asks for the 3D card |
| [5] `-w` | `GameApp::ParseCommandLine` | No skip over a quoted path, so a path with a space parses no flags |
| [2] Rear-view flashing | `CameraObject::ViewIt` | No `D3DRend::FlushBatch(0)` before the camera changes |
| [3] Rear-view alignment | `DDraw` HUD surface setup | Shot camera inset 25 by 23, or 24 under Direct3D |
| [3] Rear-view alignment | `D3DViewport::SetForTexture` | The width is not rounded up to a multiple of four |
| [4] Win2K text | `CDDTextSurface::RenderText` | The fill colour is a surface pixel value, and there is no `SetBkMode` |
| [4] Win2K text | `CDDTextSurface::RestoreContents` | Both colours are passed as `DIBINDEX` values |
| [1] 3D by default | `g_bForceSoftwareRender` | Starts at 1, so the game renders in software unless `-x` clears it |

These live functions also differ, and are marked but not yet fenced:

- `Texture::SetColorMode`, `SetScrollColorMode` and `SetFillColor` turn colours into surface pixel
  values, the scroll and fill colours through `DIBINDEX`. This is more of readme item [4].
- `DDraw::FlipOrBlt` has no full-screen test, so a windowed v1.0.0.0 game flips.
- `SoundChannel` is 0x4c bytes, with no ring fields.
- `UIScreen::~UIScreen` does not free `m_pLockedFlags`.
- `AwardsUIScreen::OnExitTabClick` tests a getter's address, not its result, so it always goes to
  the drome exterior.
- `SaveLoadUIScreen` keeps its return state at +0x470, not +0x478.
- `Spline::EvalUpperHalf` and `EvalLowerHalf` compute the same square root in a different order.

## Code only v1.0.0.0 has

v1.0.0.0's incremental link kept every function it compiled, whether or not anything called it.
v1.0.0.1's `/OPT:REF` link dropped the rest, so this code exists only in the 1996 image. 166 of
those functions are written, each inside `#ifdef HYPERX_V100` with a `HYPERX100` marker alone. They
compile but have not been run, and nothing calls them, so they are for reference and for finishing
later. Behaviour is kept as the original has it, bugs included, with a `TODO:` line where a type or
a name is a guess.

| Area | What is there |
|---|---|
| Season catalogue | `GameCatalog` reads `year.cat` (`SeasonCount`, `TournamentCount`, `SecretCount`, `DefineGame` blocks). It is unfinished: every game lands in one record, and `gameindex` is read and dropped. No `year.cat` ships with the game |
| File writers | `ColorPalette` writes `Custom.pal` and seven `.wbp` palette files; `KeyConfigDialog::SaveKeys` writes the key file; `Wave` writes `.wav` files; `ModelComponent::PrintMaterials` |
| Debug overlays | `DebugOverlay`: per-dromer energy, polygon counters, two message logs and the text stacks |
| Graphics | `DepthSort` bucket sorting, `FrameBitmap`, the `PassBar` meter surface, `CD3DTexture` constructors, the GIF block readers in `CGPalette`, `DDraw::BltZoom` |
| Maths and physics | `TransformObject` products and rotations, `SplineCurve` and `Spline` helpers, `SlerpWalk`, `Quat::MultiplyInPlace`, `PhysicsBody::GetTimeToApex` |
| Other | `PageMngm` stubs, `StringV100` string helpers, `PlanVMV100::SkipComment`, `SoundManager` group lookups, `JoystickMgr` polling, `Widget` setters |

The second pass added `FrameBitmap`'s constructors, destructor and `RestoreContents`, `PassBar`'s
own virtual overrides, the `Vec2` normalise helpers and `CRelaxToPosition::SetDest`, among others.

[v1000_cutting_room.md](v1000_cutting_room.md) lists the cut and unfinished content worth restoring.

## Not done

- The live differences listed above are marked, not fenced.
- v1.0.0.1 adds the IJG JPEG library. v1.0.0.0 already has `CD3DTexture`; how each build loads
  textures has not been compared function by function.
- About 1,200 small v1.0.0.0 functions are unmarked: mostly compiler-generated, some empty stubs
  that nothing names, and the extra copies of duplicated functions.
- The C runtime is Visual C++ 4.0's library and is not marked.
- The link order is v1.0.0.1's.
